The Architecture: Code-Diver + Institutional Memory

A complementary dual-engine retrieval pipeline: HARS Memory provides the architectural compass in 160ms, while Code-Diver executes pinpoint AST and lexical code extraction.

Hierarchical Adaptive Retrieval System linking cross-repository topologies, postmortems, and deployment relationships.

Code-Diver Hybrid Search

High-precision AST-aware code navigation and bounded reading engine.

  • 🌲 Tree-sitter AST Symbol Indexing: Identifies structs, functions, alert rules, and CRD specs natively.

  • 🇬🇧 Strict English Search Protocol: Translates user requests into codebase tokens, synthesizing final answers in user language.

LEADERSHIP & ENGINEERING FAQ

Frequently Asked Questions

Addressing core architectural, security, and operational questions from SRE and engineering leadership.

Q: Why the philosophy of "DO LESS"?

Traditional agents waste 20+ steps blindly grep'ing directories and filling context windows. Pier Do Less inverts this: Memory gives the map in 160ms, Code-Diver pinpoints the line in 2 steps, and the agent generates the fix. Fewer steps mean lower costs, zero token bloat, and zero tool errors.

Q: How is institutional memory kept fresh?

HARS connects directly to VCS commit hooks, YouTrack issue resolutions, and Slack postmortem threads. When an incident is closed or an alert rule modified, the knowledge graph incrementally updates in seconds without full-cluster rebuilds.

Q: What about compliance & sensitive credentials?

Pier operates completely inside JetBrains perimeter. With the local Gemma 4 MLX configuration, all reasoning occurs 100% on-device on Apple Silicon GPU with zero egress to third-party model providers.

Q: How does this integrate with developer tooling?

Through standard Model Context Protocol (MCP) shims. Any agent—OpenCode, Claude Code, JetBrains Junie, or local CLI scripts—can consume code_diver_search and memory_recall with zero harness lock-in.
